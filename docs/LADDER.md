# Compute-optimal ladder: BPE Transformer vs 1-stage H-Net (blog Part I recipe)

Generated by `scripts/ladder/make_ladder.py` (options: 4.3 bytes/token, vocab 32768, dataset `mix_v1`, 2048 tokens <-> 8832 bytes per window). Do not edit by hand; rerun:

```
python scripts/ladder/make_ladder.py --bytes-per-token <measured> --vocab 32768 --dataset mix_v1
python scripts/ladder/make_ladder.py --check   # tests/test_ladder.py fails when the committed files are stale
```

## Recipe

* **BPE rung LNN** (Cartesia Part I): depth L; D = nearest multiple of 128 to 75 L (floor 256: L03/L04); MHA with L heads of 128 (attention width 128 L, larger than D); SwiGLU width = nearest multiple of 128 to 3.6 D; global causal attention, full RoPE (theta 1e4), untied embeddings, vocab 32768.
* **H-Net rung** (`hnet`): main network = the identical Transformer (same D, depth, heads x head_dim, MLP; runs at 1/4.3 positions per byte = one per BPE token); 1 stage, target ratio = bytes/token, pinned by the rank decider (`dc.decision: quantile`) with the `end_mlp` router; Mamba-2 encoder/decoder at width d0 sized so stage-0 FLOPs/byte (encoder + decoder + router + residual_proj + byte LM head + chunk-vocab head) equal BPE's embedding + LM-head FLOPs/byte (within 1%); the parameter budget left after the outer network is filled with FLOP-free hashed tables at width d0: the chunk vocabulary (`dc.chunk_vocab`, 2 hashes, 64% of the rows, next-chunk objective pred_weight 0.5 / 1024 negatives) and byte n-gram tables (`ngram_embed`, n = 3..8). `router_prior_weight` 0.
* **`hnet_ws`**: `hnet` + whitespace warm start (`router_prior_weight` 1.0, `router_prior_frac` 0.1). Same params and FLOPs.
* **FLOPs**: `hnet.flops` SPEC convention: causal attention, LM head counted, embedding / table lookups free, backward = 2 x forward. Stage-0 FLOPs include the training-only chunk-vocab head.
* **Training**: Muon (hidden matrices) + Adam (embeddings, tables, heads, norms, router), WSD 10% warmup / 20% 1-sqrt decay (`configs/runs/_core.yaml`), Muon momentum ramp 0.85 -> 0.95 over min(300, 10% of steps), bf16. Muon LR from the tuning sweep (blog: BPE's hyperparameters transferred to the H-Net), Adam-part LR 0.003 (fixed). Same steps, windows per step and therefore the same text for all three architectures of a rung.

## Iso-FLOP sweeps

Chinchilla prior: T = 20 N (N = backbone params); per budget the 5 rungs closest to the prior in log(T/N). Each (budget, rung) is one spec with three runs (bpe, hnet, hnet_ws); the fairness gate (`scripts/search/fairness.py`, strict) holds FLOPs/byte and bytes within 2% inside a spec. Steps = round(T / tokens per step); the BPE run trains steps x batch tokens, the H-Nets steps x batch bytes. Specs need `--params-file` from the LR sweep (or `--param best_mlr.bpe=...`).

## Deviations from the blog and open issues

* Vocabulary 32768 in-corpus BPE (blog: 128k, 4.57 bytes/token); bytes/token 4.3 is a placeholder until measured. The fairness gate reads the measured value from `hnet/data/bpt_stats.json` (dataset `mix_v1`), so it fails until the dataset is measured and the ladder regenerated with that value (`--bytes-per-token`).
* Rungs L03..L12 (blog: L08..L28); D floor 256 makes L03/L04 share D = 256.
* Outer network design is not published: Mamba-2 stacks, width and d_state searched per rung for FLOP matching (so they vary irregularly between rungs); parameter matching uses chunk-vocabulary and n-gram tables (ours, not the blog's).
* Matching uses target compression (ratio = bytes/token); the rank decider pins it, but realized bytes/position should be checked in the runs (`hnet.flops.model_flops(..., bytes_per_position=...)`).
* Batch and LR scaling laws are not fitted (blog: fitted on selected rungs). Batch follows ~C^(1/3) from 0.5M tokens at 1e18; the Muon LR is tuned once at the smallest budget and transferred; the Adam-part LR is fixed. Small-rung / small-budget runs have few steps (see tables).
* SPEC FLOPs convention (standard causal attention), not the blog's Fig. 8 convention (half-cost causal).
* Data: the 70/20/5/5 mix and 32k tokenizer are built elsewhere; the BPE loader still needs the tokenizer's EOT id (`data.eot`) and byte lengths for bpb.
