The short version. Most language models first chop text into tokens using a fixed dictionary (BPE). H-Net skips that and reads raw characters, learning for itself where words and pieces begin and end. Its authors reported it beating tokenizer models. At our small scale, with equal compute, equal model size and equal data, the published design did not: it needed 11–13% more bits to predict the same text.

What we then tried. AI agents proposed, coded and tested 30 ideas over five rounds. The biggest single win was letting the model copy from earlier in the same document. Combining it with four smaller ideas, the byte-level model beat a standard model that had the same copy trick, by 1.9%.

Why it is not a win yet. At a bigger model size the order flipped. The bigger standard model learns to copy by itself, so our add-ons help it less, and they help the byte-level model less too. Small-scale wins are cheap to find and often vanish with scale; this one did.

Words used on this page
BPE / standard modelA Transformer that reads text as tokens from a fixed 32,768-entry dictionary, as most LLMs do.
H-Net / byte-level modelReads raw bytes and learns where to group them into chunks, so it needs no dictionary.
Copy trickLook up the last time the current text appeared in the same document and offer what came next. Both model types got it.
Space hintEarly in training, nudge the byte-level model to start chunks at spaces. The nudge fades to zero.
Bits per characterThe score: how surprised the model is by each new character. Lower is better; 1.0 would mean one yes/no guess per character.
Fair comparisonEvery pair used the same training compute, the same number of parameters and the same data.
