## Realized compression per source (bytes per main-network position; scratch tool source_compression.py)
Batch: 4 windows x 2048 bytes from each mix_v1_small val group (en, code, held-out code, math, multilingual), every
window its own segment, run in training mode (batch-coupled rank decisions with batch statistics: where the exact
training budget goes, i.e. the main network's FLOPs) and eval mode (running thresholds, the per_source.py
convention). in_copy16 = bytes whose preceding 16 bytes occurred earlier in the window (9.8% of these bytes); _gain0
= the same trained model with the feature gain set to 0 (isolates the feature's own effect from the router's
co-adaptation).

Readout. (1) The feature does what it is built to do on the same model: multilingual gets 17-21% more chunks
(5.03 -> 4.17, 5.79 -> 4.94 bytes per chunk), English and code 1-5% fewer, in-document copies 3-7% fewer, at the
same exact total. (2) The router co-adapts: route-01's router alone gives multilingual coarser chunks than the
parent's (5.0-5.8 vs 2.8-3.4), so the net per-source picture vs the parent is a more uniform allocation (en 5.5-6.3
-> 4.9-5.0, ml 2.8-3.4 -> 4.2-4.9), not BPE's (ml finer than en). (3) At 300 CPU steps the probe barely separates
copies (2.18 vs 2.34 nats): the match model's zero-init embeddings have not been learned yet; the copy effect is
expected to grow with training. (4) The LM loss pulls the region gain down (0.75 -> ~0.5 by step 300): the GPU
run's gain trajectory is the falsification readout. (5) Eval-mode compression is below target for parent and
candidate alike in these short smokes (2.7-3.2 vs 4.145; running statistics), so the training-mode table is the
FLOP-relevant one.
